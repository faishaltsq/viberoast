# Isolated website scanner

The Next.js process never launches Chromium. `lib/scanner/client.ts` requires `SCANNER_URL` and `SCANNER_TOKEN`, makes an authenticated, non-redirecting request to `/scan`, limits the response to 8.2 MB and 50 seconds, and validates the shared `scanSchema`. Missing configuration is an error, not a local-browser fallback.

## Run

Use a Linux Docker engine with user namespaces available to Chromium. Docker Desktop must be running when using Windows. From the repository root, supply a randomly generated secret of at least 32 characters as `SCANNER_TOKEN`, then run:

```sh
docker compose up --build -d
```

Set the web server's `SCANNER_URL=http://127.0.0.1:8787` and the same scanner token. These are scanner service credentials, **not** AI/provider credentials. Do not pass AI credentials to either container. A web server on another host needs an authenticated TLS/private-network connection instead; do not publish port 8787 on a public interface. The compose file binds it to host loopback only. The proxy has no published port. An authenticated `GET /health` on the worker reports readiness of the service, not browser or destination availability.

The worker image and JavaScript dependency both pin Playwright 1.58.2. Install the lockfile's production dependencies, including `playwright`, `sharp`, `ipaddr.js`, `tsx`, and `zod`. Builds use the lockfile and skip dependency lifecycle scripts; the Linux Sharp optional binary must be present in the lockfile resolution. No downloaded repository code is executed as part of a scan.

## Network and privilege boundary

* The worker joins `scanner-internal` for proxy traffic and a dedicated `scanner-control` bridge for the loopback-published API. Docker does not wire published ports on internal-only networks. The control bridge does not grant effective egress: the namespace OUTPUT firewall permits only established replies and new connections to the proxy. The proxy separately joins the internal and external networks. The fixed proxy subnet is `172.30.44.0/28`; changing it requires updating Compose addresses and the entrypoint allowlist together.
* Worker startup is root only long enough to install an OUTPUT firewall. Only established replies and new TCP connections to `172.30.44.2:3128` are permitted. All other new output is rejected, including loopback, Docker DNS, metadata endpoints, UDP, and private networks. IPv6 must be disabled by the container sysctls, or startup stops.
* Startup writes a root-owned, read-only isolation marker, drops UID/GID to 1000, removes all capability bounding/inheritable/ambient sets, enables no-new-privileges, and execs Node. Runtime checks require the marker, zero effective/bounding capabilities, no-new-privileges, the explicit isolation setting, and the proxy configuration. The marker is attestation by the trusted container entrypoint, not a defense against a malicious Docker operator.
* `SCANNER_ISOLATION=firewall-proxy-v1` alone is insufficient. Running `worker/start.ts scanner` on the host, bypassing the entrypoint, retaining capabilities, or omitting sysctls fails closed. There is no production test-mode bypass.
* Chromium uses `chromiumSandbox: true`; no `--no-sandbox` or public debugging port is used. The custom seccomp allowlist permits namespace syscalls needed by Chromium while retaining a default-deny syscall policy. Chromium also installs its own sandbox restrictions. If host user-namespace or Ubuntu AppArmor policy prevents sandbox startup, fix the host policy; do not remove Chromium's sandbox or use privileged containers.
* The HTTP/CONNECT proxy admits only the exact worker source IP on the unexposed internal network. It deliberately supplies **no browser proxy credentials**: Playwright's unrestricted authentication handler can otherwise offer proxy secrets to a destination's origin-auth challenge. Do not publish the proxy port or attach untrusted containers to its networks. It accepts HTTP GET/HEAD on port 80 and CONNECT only on port 443. Every returned DNS address must be public, and the approved literal IP is passed directly to the socket without a second lookup. Nonstandard ports, userinfo, noncanonical/private/reserved/transition IPs and local hostnames are rejected. HTTPS remains end-to-end and Chromium validates certificates.
* Redirects and subresources cannot bypass the OS firewall. Every new proxy connection is independently validated and DNS pinned, including public sites redirecting to private addresses. Browser routing is an additional budget/read-only policy, not the SSRF boundary. Existing pinned connections cannot rebind to a different destination.
* Keep the worker in its own PID namespace and do not run unrelated UID-1000 services in it. Each scan is a subprocess. At completion, timeout, or client disconnect, the parent kills the child and any remaining UID-1000 processes except itself, covering Chromium's separate process groups. Docker init reaps descendants. Do not share the host PID namespace or mount the Docker socket.

Both containers have read-only roots, limited tmpfs, dropped capabilities after setup, CPU/memory/PID/file-descriptor limits, and no host filesystem mounts. The worker's temporary NET_ADMIN/SETUID/SETGID/SETPCAP capabilities are used by the entrypoint only. Do not add NET_ADMIN back to the runtime process. This boundary trusts the Linux kernel, Docker network/firewall implementation, pinned runtime dependencies and deployment operator; it is not a claim of protection against kernel/browser zero-days. Rebuild images for security updates and review the policy when upgrading Chromium.

## Bounded passive observations

The worker admits one scan at a time; concurrent submissions receive 429. JSON request bodies are limited to 4096 bytes, headers to 8192 bytes. A scan subprocess is killed after 44 seconds; the service deadline is 46 seconds. Browser operations have separate timeouts, and the browser closes at its internal deadline. Each viewport navigation is limited to 12 seconds, then a 700 ms rendering settle period and a maximum one-second font-readiness wait; this is not a full-load or Core Web Vitals measurement.

A fresh unauthenticated browser context is used for each desktop (1440 × 900) and mobile (390 × 844) visit. No cookies/storage/auth state are imported or retained across visits; a public site can set transient anonymous cookies during its own visit. Script-supplied Authorization headers, non-GET/HEAD requests, service workers, downloads, popups and WebSockets are blocked. The HTTP proxy additionally strips Cookie headers; HTTPS stays opaque and does not promise cookie interception. No clicks, sign-in, form submissions, crawling or active security tests occur. Sites may still execute their own JavaScript during passive rendering.

The browser budget is 140 observed requests across both views, eight redirects per chain and 24 MB of completed response bodies. Redirect/request events also close the context when budgets are crossed, including redirects that Playwright does not re-route. Streaming traffic is independently bounded by the proxy: 48 MB aggregate traffic, 400 source-admitted requests/tunnels per fixed reset window of 60 seconds, 32 active requests/tunnels, 40 TCP clients and a 15-second lifetime per upstream operation. The proxy's shared fixed-window budget can cause a subsequent scan to be partial until reset. Encrypted CONNECT traffic counts toward the same byte ceiling.

DOM extraction walks at most 5000 elements and samples headings, links, buttons, form structure/accessible labels, image alt/load state, viewport size and computed text styles. It never extracts field values. Text, metadata and URLs are redacted before output; URL queries/fragments/userinfo are removed and common credentials/email addresses are removed from text. Console messages and request URLs are not retained, only bounded counts. Screenshot form fields are masked. If recognized credentials or incompletely inspected content could be visible, **both screenshots are omitted**, with an explicit warning. Otherwise viewport JPEGs are resized to a longest edge of 1280 pixels and less than 600000 data-URL characters each. Screenshots are not full-page captures. Redaction is best-effort for arbitrary public-page personal data and cannot recognize secrets rendered inside images/canvas; only submit public pages you are authorized to inspect.

Findings are deterministic DOM/metadata/layout observations with stable IDs, evidence, severity, confidence and verification status. Button-name sampling is explicitly heuristic; it does not pretend to replace the accessibility tree. Network failures, DOM truncation, missing viewports/screenshots or budget exhaustion produce partial status and warnings. Unsupported non-HTML responses are not inspected. HTTP error pages and heuristically detected bot/access challenges are disclosed as partial and excluded from target-page findings/strengths; challenges are never bypassed. If no HTML document can be inspected, the request fails instead of returning an invented report. Successful scans still disclose their passive/sampled scope. No absence-of-errors, security, SEO-ranking, WCAG-compliance or performance certification is inferred.

## Test seams and verification

Exported helpers include `normalizePublicUrl`, `isPublicIp`, `assertPublicDestination` (injectable DNS resolver), `redactSecrets`, `redactUrl`, `readBoundedResponse`, `extractDocument`, `extractPage`, `isChallengePage`, `buildFindings`, `captureScreenshot`, `resolveProxyTarget`, `credentialsMatch`, `createEgressProxy`, `createScannerServer` and `assertIsolation`. Server injection supports controlled tests only; `worker/start.ts` always selects the real implementation and asserts isolation. Production `executeScan` also checks isolation before spawning.

`tests/scanner.test.ts` covers unsafe/alternate addresses, mixed DNS answers, approved socket identities, CONNECT policy, full-value secret redaction, missing isolation/configuration, response size, real HTTP authentication/body limits, challenge recognition and deterministic findings. Browser extraction can be exercised with `page.setContent` and `extractPage` using an isolated controlled fixture; that does not authorize a local production scanner fallback. For deployment verification, check authenticated health, one public scan, a private-address rejection, direct socket/DNS/loopback rejection from the running non-root worker, zero runtime capabilities, active sandbox, and timeout process cleanup. Do not claim these native checks passed merely because compose parsed or an image built.
